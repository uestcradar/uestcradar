# 测角符号（左右/上下判别）失效的成因说明

本文说明：为什么修好角度**幅值**之后，角度**符号**仍然系统性判错；符号究竟从哪里来、为什么会被硬件相位破坏、"加一个固定偏转角"到底能不能绕过去。文中出现的所有符号都附中文标注。

数据来源：`E:\0916\RX\right_256\capture_20260916_075548_3d30dead_ch012`（0916 采集），波位 26（方位中心 `c_b` = +10°，俯仰中心 = +5°），真值来自 `F:\RTK\right256.SRT`。

---

## 0. 结论（先看这段）

比幅单脉冲的两个量分工是分开的：

- **角度幅值** 藏在模值 `|Δ/Σ|` 里 —— 对接收链路相位**完全免疫**，所以修好前缀起点后幅值立刻对得上；
- **侧别符号**（偏左还是偏右）藏在 `Δ/Σ` 的**相位**里 —— 而相位里含一个由硬件决定的固定失配 `φ`（判别器相位）。

而单脉冲的理想复比值是**纯虚数**，所以侧别信息本来就在虚轴上，`Re(Δ/Σ)`（实部）是一个**名义上为零的残差**。原代码 `sign(Re(Δ/Σ))` 取的就是这个残差。

本批实测 `φ` = −93.5°，与 `φ_used` = 0° 相差 93.5°。判符号的正确窗口是以 `φ` 为中心、宽 180° 的区间，**0° 恰好在窗口外 3.5°**——所以符号整体取反；又因为此时投影只剩 6%，噪声掩盖了一部分，表现为"几乎恒为 −1"而不是干脆的 100% 出错。

## 2. 符号从哪里来

### 2.1 理想单脉冲的复比值是纯虚数

以两子阵为最简模型（真实阵列同构，只是把 `β` 换成一个正比系数）：设两子阵收到的信号幅度相同、相位相差 `2βδ`（`β` = 子阵相位常数，`δ` = 离轴角），则

```
Σ_ant ≈ A · ( e^(+iβδ) + e^(−iβδ) ) = 2A · cos(βδ)
Δ_ant ≈ A · ( e^(+iβδ) − e^(−iβδ) ) = 2iA · sin(βδ)
```

相除得

```
Δ_ant / Σ_ant = i · tan(βδ)
```

**这是关键**：理想口面比值是**纯虚数**。

- 模值 `|Δ_ant/Σ_ant| = |tan(βδ)|` —— 关于 `δ` = 0 对称的 V 形，谷底在中心，**只含角度幅值、不含侧别**；
- 相位：`δ` > 0 时为 +90°，`δ` < 0 时为 −90° —— **侧别信息全部在虚轴上，实部恒为零**。

### 2.2 接收链路把这条轴整体旋转了

数字域拿到的不是口面信号。每条链路有各自的复传递函数：

```
Δ = Δ_ant · g_Δ
Σ = Σ_ant · g_Σ
```

于是

```
c = Δ / Σ = i · tan(βδ) · e^( i·φ_chain )      其中 φ_chain = arg( g_Δ / g_Σ )
```

两段取值：

| 情况 | `arg(c)` | 说明 |
| --- | --- | --- |
| `δ` > 0 | `φ_chain` + 90° | 记为 **φ**（本文的操作性定义） |
| `δ` < 0 | `φ_chain` − 90° = φ + 180° | 与上一支恒差 180° |
| `δ` = 0 | 无定义 | `\|c\|` = 0，谷底 |

所以 **`φ` = `φ_chain` + 90°，天然落在虚轴（±90°）附近**，具体偏离多少由链路失配决定。实测本批 `φ` = −93.5°，即链路失配只有 3.5°——**这条通道其实相当匹配，问题出在代码没有把它算进去**。

### 2.3 由此得到核心结论

- **模值免疫**：`|c| = |tan(βδ)|`，相位被彻底约掉 ⇒ 相位失配**不影响角度幅值**；
- **符号不免疫**：侧别由 `arg(c)` 落在哪一半平面决定，而 `arg(c)` 含 `φ` ⇒ 相位失配**直接决定符号对错**。

## 3. 为什么 `sign(Re(·))` 等于假定 `φ` = 0°

### 3.1 投影公式

把复比值向方向 `φ_used` 投影，投影值（带符号）为

```
proj = Re( c · e^(−i·φ_used) ) = |c| · cos( arg(c) − φ_used )
```

代入 2.2 的两支取值（记 `Δφ = φ_used − φ`）：

```
δ > 0 : proj = |c| · cos( φ − φ_used )      = |c| · cos(Δφ)
δ < 0 : proj = |c| · cos( φ + 180° − φ_used ) = −|c| · cos(Δφ)
```

合并：

```
proj = sign(δ) · |c| · cos(Δφ)
sign(proj) = sign(δ) · sign( cos(Δφ) )
```

### 3.2 两条推论

1. **正确性窗口**：只要 `|Δφ|` < 90°，`cos(Δφ)` > 0，**所有点的符号都正确**；一旦 `|Δφ|` > 90°，全部反号。窗口以 `φ` 为中心、宽 180°。
2. **投影幅度**：`|c|·|cos(Δφ)|` —— 在 `Δφ` = 0 时最大，在窗口边缘降到 0。**越靠边缘，符号越由噪声决定。**
3. 原代码 `sign(Re(c))` 即 `φ_used` = 0°，也就是 `Δφ` = `−φ`。它不是"少算了一个修正量"，而是**明确假设了链路相位失配不存在，同时把 2.1 那个固有的 90° 正交也当成了 0**。

### 3.3 本批为什么越坎

| 量 | 值 |
| --- | --- |
| `φ`（实测） | −93.5° |
| `φ_used`（原代码） | 0° |
| `Δφ` | **+93.5°**（越过 90° 边缘 3.5°） |
| `cos(Δφ)` | **−0.061** |

所以：符号整体取反，**但投影只剩 6%**，噪声掩盖了一部分 ⇒ 实测符号正确率 62.3%（不是干脆的 0%）。

这也精确解释了观测到的 `Re(Δaz/Σ)` 的样子：它是**名义上为零的残差**，实测 114 帧中 99 帧为负、`|Re|` 多在 0.004~0.4，且**与目标在中心的哪一侧基本无关**——因为它本就是被噪声和微小偏置主导的量。

### 3.4 几何图像

```
                          Im（虚轴）
                            ↑
             δ<0 侧射线  ╱  arg(c) ≈ +93.7°
                        ╱
                       ╱
     ●────────────────●────────────────→ Re（实轴）
                       ╲        ↑
                        ╲       └─ sign(Re(·)) 就是往这条水平轴上投影
             δ>0 侧射线  ╲  arg(c) ≈ −100.7°
                            ↓
```

`δ` > 0 与 `δ` < 0 的两条射线几乎共线（实测相差 194.4°，理想应为 180°），整条轴几乎贴着虚轴。往水平轴上投影，得到的值 `∝ cos(≈90°)` ≈ 0 —— **取到的正是没有侧别信息的那一根轴**。

### 4.1 目标格上的复比值相位（61 帧，`|δaz_true|` ≤ ROI）

| 两支取中间得到的 `φ` | **−93.5°** |

### 4.2 扫 `φ_used` 看符号正确率

| `φ_used` | `Δφ` = `φ_used` − (−93.5°) | \|cos(Δφ)\| | 符号正确率 |

| `Re(Δaz/Σ)` | 接近零的小残差、整体偏负，114 帧中 99 帧为负，**与侧别无关** |

本批 `δel_true` ∈ [−2.21°, −0.83°]，**全程为负**，所以俯仰符号**全部应为 −1** —— 这是一条不需要真值大小、只用"目标在俯仰波束中心下方"的强约束。

| 量 | 实测值 |
| --- | --- |
| 全部 61 帧同号的 `φ_el` 区间 | **[−138°, −52°]**（宽 86°） |
| 该区间中心 | **−95°** |

方位（−93.5°）与俯仰（−95°）两条路线给出的 `φ` 吻合到 1.5°。需注意本批 `δaz` 与 `δel` 严格共线（相关系数 +1.000），两条线索并非完全独立，但两个通道结论一致仍是有力佐证。（该约束宽度 86° 接近 3.2 所述 180° 窗口的一半，属"单边不过零"航线固有的信息量上限，无法把 `φ_el` 定位到点。）

### 4.4 口径差异说明（诚实记录）

用"端到端"口径（CFAR → DBSCAN → `mono_angle`，48 帧）得到的 100% 平台是 **[−135°, −90°]**；用"原始目标格"口径（61 帧）得到的是 **[−98°, −88°]**。两者不一致的原因是取的帧集合不同，且"100% 严格"这一判据实际由**最差的那一帧**决定，边缘很脆。稳健的表述是：

> **起作用的 `φ` 在 [−140°, −85°] 区间内，与 0° 相差 90° 以上。**

工程上取区间中部即可（当前配置 `cfg.angle.phi_az` = −113° 即按此选取）。

## 5. "加一个固定偏转角"到底行不行

这个问题需要分层回答。**结论是：能救这一次，但不是可靠工程手段**——本文初版把这一条答成了"完全不行"，是错的，原因是混用了 `φ` 的两套定义。

### 5.1 投影幅度在 `φ_used` = `φ` 时最大

由 3.1，投影幅度正比于 `|cos(Δφ)|`：

| \|Δφ\| | 0° | 20° | 45° | 70° | 90° |
| --- | --- | --- | --- | --- | --- |
| 投影因子 \|cos(Δφ)\| | 1.00 | 0.94 | 0.71 | 0.34 | 0.00 |

`φ_used` = `φ` 已经是**幅度上的最优解**，任何固定偏转都会降低信噪比。

### 5.2 但"正确性窗口"有 180° 宽，所以固定偏角在边缘附近确实能救

本批 `φ` = −93.5°，正确性窗口为 `φ_used` ∈ (−183.5°, −3.5°)。`φ_used` = 0° 只在窗口**外 3.5°**——这是"越坎"显得那么干脆的原因，也是**它的脆弱之处：边缘就在 0° 附近**。

若当初固定加 −20°（`φ_used` = −20°），落在窗口内 16.5°，实测 90.2%（对比 0° 的 62.3%）。**所以这个办法确实能救。** 但代价与风险是：

1. 只买到 `|cos(73.5°)|` = 28% 的投影幅度，波束中心附近的点仍会被噪声翻掉（90.2% ≠ 100%）；
2. 窗口单侧裕量只有 16.5°，而 `φ` 随频率、批次变化可达几十度（厂商明确说明"和口到子阵与差口到子阵的 S21 相位差在同一批次内比较恒定，但不同频率的差值不一样，且需连同接收机一起校准"）；
3. 能救纯属"0° 离边缘只有 3.5°"的巧合。**这个巧合不可复用**：下一批数据的 `φ` 若变成 −150°，窗口移到 (−240°, −60°)，`φ_used` = −20° 就又跑到窗口外了。

### 5.3 结论

固定偏角是**碰运气**：它的成败取决于 `φ` 是否恰好落在某个 180° 窗口内，而窗口边缘与常用值 0° 的距离完全由硬件决定。正确做法是**测量 `φ`**（见第 7 节）。若因条件限制只能先给一个固定值，应取 **`φ` 经验区间的中心**并清楚它只是把错误率压低、不能消除，且**每换批次/频点都必须重测**。

## 6. 曾经误导过、现已排除的几条

| 说法 | 为什么错 |
| --- | --- |
| "符号位失效了" | 硬件符号位没有失效。是**代码取错了复平面的分量**：理想的 `Re(·)` 分量本就恒为零。 |
| "加个固定偏转角完全没用" | 见第 5 节：在窗口边缘附近它确实有效，只是不可靠。 |
| "用 X256B 远场方向图标定符号" | 该方向图的和口与差口相隔约 28 分钟测量，**两口的相对相位完全不可信**。其幅度/形状可用，相位不可用。 |
| "从噪声门估通道相位失配" | 两个**独立**复高斯噪声之比的相位是**均匀分布**，其圆均值收敛到 0 附近的随机方向，估不出任何失配。该统计量在数学上无效。 |
| "测角结果与真值相关 0.91~0.99，所以符号没问题" | 该相关性是在**通道互换**之前、用错口的通道算出来的，且本批 `δaz` 与 `δel` 严格共线（+1.000），**用错的通道照样与真方位强相关**。相关性强不能证明符号正确——只有**符号正确率**能。 |

## 7. 可行路径与当前实测状态

| **直达波作差分参考** | 直达波是确定性的共模漏泄，其 `arg(R_dw) = φ + Ψ − 90°`，`Ψ` 为硬件常量 | 一次偏置标定 | 见 7.1，已实测 |

### 7.1 直达波作为 `φ` 的差分参考（已实测）

直达波是 TX 数字域到 RX 数字域的**内部漏泄**，位置由硬件流水延迟决定（实测固定在距离门 204），每个波位、每个 PRI 完全相同。

**稳定性实测**（`src/estimate_phi_from_dw.m`，三个独立采集，同日 07:20 / 07:21 / 07:55）：

| 数据集 | 峰值距离门 | 40 驻留峰噪比(中位) | \|ch1/ch0\| ∠（俯仰） | \|ch2/ch0\| ∠（方位） |

幅度一致到 1.5%，相位一致到 1.1°，跨波位结果一致。**这是一个稳定的硬件常量。**

> **⚠ 口径更正（2026-09-30）**：本节此前记录的是 `\arg(R_dw)_az ≈ −143.5°`、`|ch2/ch0| ≈ 0.52`、
> `arg(R_dw)_el ≈ −155°`、`|ch1/ch0| ≈ 0.21`。那组数来自早期脚本 `diag_dw_phi.m` /
> `diag_dw_stability.m`，它们**没有复现 RD 链的处理**：不做逐通道去均值、不加窗。
>
> 这两步**都不是共模、不抵消** —— 去均值是逐通道的（各通道直流不同），加窗则通过两个通道
> 信号形状不同进入比值（`pc_2/pc_0` 是两个和之比，参考上的公共因子并不约掉）。
> 而 `φ` 是在 **RD 链**上标定的（`diag_phi_plateau.m` 读 `RD_Proc_*.mat`），所以旧口径测出的
> `arg(R_dw)` 与它要配的 `φ` 不同链，反推出的补偿量被偏置了约 5°（方位）/ 11°（俯仰）。
>
> 现口径逐字复现 `preprocess.m`（逐通道去均值 → 加窗匹配滤波）。管线后续的 MTI、循环移位
> 都是**三通道共模**（比值里抵消），所以两链条对比值相位等价 —— 这也是为什么只需复现到
> 匹配滤波为止。**幅度会随链条变（0.52 → 0.70），但运行时只用相位，幅度仅作诊断。**

**但它不是绝对 `φ`**：`arg(R_dw)` 与真正起作用的 `φ` 相差约 45°。成因自洽：三个通道的直达波比值各不相同（0.31 / 0.70），说明漏泄是以不同路径进三条链的，比值里含有固定的耦合相位差。令 **Ψ = 漏泄注入点处"差口耦合 / 和口耦合"的相位差**，则

```
arg(R_dw) = Ψ + φ_chain        （漏泄比值带上耦合相位 Ψ，再乘链路失配）
          = Ψ + (φ − 90°)       （由 §2.2：φ = φ_chain + 90°）

   ⇒   φ = arg(R_dw) + (90° − Ψ)
```

**工程上只保留最后那个括号，不要再引入 `K`。** 把它定义成补偿量，存进配置： 

```matlab
phi_correction = 90 - Psi_deg;                    % 标定一次的常数（单位：度）
phi_az = wrap180(angle(Rdw_az)*180/pi + phi_correction_az);
phi_el = wrap180(angle(Rdw_el)*180/pi + phi_correction_el);
```

> 落代码时注意单位：现有代码路径全程用度（`cfg.angle.phi_az = -113`、`exp(-1i*deg2rad(phi_az))`），
> 而 MATLAB 的 `wrapToPi` 收弧度。若配置项保持为度，就用 `wrap180(x) = mod(x + 180, 360) - 180`，
> 不要写成 `wrapToPi(...)` 配度值——那是另一种正负号事故。

标定值（新口径，由"已知 φ − 实测 arg(R_dw)"反推，括号内为三个独立采集的结果）：

| 量 | 数值 | 来源与可信度 |
| --- | --- | --- |
| `phi_correction_az` | **+45°**（44.8 / 45.3 / 45.9） | 由 `φ_az = −93.5°` 反推；φ_az 来自 100% 同号平台，可信到 ±5° |
| `phi_correction_el` | **+49°**（48.7 / 48.9 / 49.0） | 由 `φ_el = −95°` 反推，但**该 φ_el 本身未标定**（§7.2），故此值只是暂定 |

**验算**：−138.8 + 45 = −93.8 ✓（本批方位 `arg(R_dw)_az` ≈ −138.8°）；−143.9 + 49 = −94.9 ✓。

> **俯仰那一行要当心**：`phi_correction_el` 在三次采集间稳定到 0.3°，说明**测量**可重复；
> 但它是相对一个 ±43° 不确定的 `φ_el` 反推的，所以**绝对值没有被钉住**。
> 可重复 ≠ 已标定。要钉住必须飞一条俯仰剖面航线（§7.2）。

> **为什么必须弃用 `K`**：同一个物理量若同时存在"物理耦合相位"与"代码里相加的补偿量"两种口径，
> 二者数值**恰好反号**。本文初版即把两者都叫 `K`，直接导致 7.1 出现
> `arg(R_dw) = φ + arg(K)` 与 `φ = arg(R_dw) + arg(K)` 两个互相矛盾的公式（前式对、后式错）。
> 补偿量口径的好处是：**存进配置文件的就是代码里实际相加的那个数**，
> 正负号没有第二种解释，也就无法被解释错。

**所以它买到的能力是：**

1. 直接当 `φ` 用（补偿量取 0）→ 方位 95.1%（61 帧错 3 帧），**略差于**已标定的 −93.5°（100%）；
2. 标定一次 `phi_correction` 后，`φ = wrap180(arg(R_dw) + phi_correction)` 可以在每次运行时零成本测出（40 驻留 × 64 脉冲）。
3. **有效性边界**：只在漂移发生在漏泄**注入点下游**时成立。上游（馈线/电缆）漂移只动 `φ` 不动 `arg(R_dw)` ⇒ **静默失效**（仍返回稳定值，但已不对）。

> **⚠ 上面第 2 条已被 §7.4b 的实测否定，本节的方案随之作废。**
> 当时假设"`φ` 的任何漂移都会 1:1 反映在 `arg(R_dw)` 上"，实测不成立：相隔 12 天，
> `φ_az` 只动了 11°，而 `arg(R_dw)_az` 动了 **96°** —— **二者解耦**。于是 `phi_correction`
> 必须每次会话重标（0916 为 +45°、0928 为 −51…−62°），而用过期值会**自信地输出错 `φ`**
> （0928 数据实测同号率仅 14.5%）。这正是上面第 3 条边界所说的"上游漂移"在真实数据里发生了。
> **结论：不要把直达波接进管线。** `φ` 本身稳定，直接硬编码 + 跑 `sign_selfcheck.m` 即可（§7.5）。
> 模块 `src/estimate_phi_from_dw.m` 与 `test_estimate_phi_from_dw.m` 保留备查，仅可手动调用复核。

### 7.2 未验证项

- **仅单一频点（9.5 GHz）**，无法验证 `Ψ` 是否随频率变化。厂商明确说明相位差随频率变，因此 **`phi_correction` 很可能也随频率变；换频点必须重标 `phi_correction`**。
- `φ_el` 未能精确标定：本批 `δel_true` 全程不过零，约束只能把 `φ_el` 限在 86° 宽的区间内。需要一条俯仰剖面的飞行。

### 7.3 符号自检（已实现）

**`src/sign_selfcheck.m`**，累加量由 `mono_angle.m` 的 `angle_stats` 提供，在
`apps/run_batch_pipeline.m` 的 `[测角统计]` 之后打印一行结论。

不需要真值、不需要标定航线、不需要额外数据 —— 只用已有的目标格。原理就是把 §3 的投影反过来
用：目标簇上 `|Re(c·e^{-iφ_used})|/|c| = |cos Δφ|`，**与侧别无关**，于是可以直接读出
"当前 φ 所在的轴距判别器轴有多远"。它衡量的是**裕量**，不是"符号当下对不对"。

|φ_used|eff|判定|说明|
| --- | --- | --- | --- |
| −93.5°（真值） | 0.974 | ok | 距翻号边界余 76° |
| −113°（旧配置） | 0.912 | ok | 余 66° |
| −138.8°（= `arg(R_dw)_az`） | 0.65 | warn | 余 39°，量程已损失 35% |
| **0°（0916 失效配置）** | **0.115** | **fail** | 余 7°，符号被固定偏置主导 |

> 最后一行是这个自检的存在理由：**φ = 0 时同号率还有 60.7%，单看同号率不像坏了**；
> 而 eff 直接读到 0.115 并报 fail。比事后数同号率灵敏得多，且不需要真值。
>
> 第三行顺带说明**直达波为什么不能直接当 φ**：`arg(R_dw)` 距真值 45°，虽仍在 90° 窗内
> （所以"直接用"还能有 95% 同号率），但裕量已只剩 39°，warn 档 —— 必须配补偿量才能用。

随机相位地板实测 0.636、理论 2/π = 0.637，与模型一致。合成数据回归见
`test_sign_selfcheck.m`（φ 正确 → 1.000/ok；φ+90° → 0.000/fail；`|Δφ|` 反推误差 0.0°）。

**已知局限**：① 假设累加的目标格里以真目标为主，杂波相位近似均匀会把 eff 往 0.637 地板拉，
故只能同口径横向比较；② 它不产生任何剔除或回落行为，多目标场景下不引入新行为。

### 7.4 跨批次稳定性实测：同场次内检不出漂移（**仍未覆盖跨上电/跨天**）

`phi_correction` 只有"**不漂**"才值得用，所以要量的是漂移。方法学上关键是要把**漂移**
和**测量噪声**分开 —— 每个数据集内部有 40 个驻留，驻留之间的散布就是纯测量噪声，
拿它当标尺去量数据集之间的散布：

| 轴 | 组内 IQR（中位，= 测量噪声） | 组间极差 | 组间标准差 | **组间/组内** |
| --- | --- | --- | --- | --- |
| 方位 | 1.8° | 1.8° | 0.6° | **0.36** |
| 俯仰 | 2.3° | 2.0° | 0.7° | **0.32** |

**组间散布比组内噪声还小** ⇒ 跨数据集的差异被测量噪声完全解释，**检不出真实漂移**。
（判据：比值 ≈1 说明没检出；要到 2~3 才算有真实漂移。）

6 个数据集的 `arg(R_dw)_az`：−140.1 / −138.6 / −139.0 / −138.8 / −139.4 / −138.3°；
峰值距离门六个全是 **204**（含 128 脉冲配置）；`|R|` 只散 3.0%（方位）/ 2.0%（俯仰）。

**这个结论的边界必须说清楚，别当成"φ 不会漂"：** 这 6 个数据集**全部**在 2026-09-16 的
06:34~07:55（82 分钟内），所以只覆盖了**跨航次 / 跨指向 / 跨脉冲配置（128 vs 256）**，
**不覆盖跨上电、跨天、跨温漂** —— 而后者才是"换一批数据还算不算数"真正要问的情形。
（**该缺口已由 §7.4b 用 2026-09-28 的数据补上。**）

**跨硬件配置则完全不同**：另一套 100 阵元的采集（2026-07-06，`30M_100tao_E2`）里直达波在
距离门 **123**（不是 204），`arg(R_dw)_az = −60.5°`、`arg(R_dw)_el = +57.6°`、
`|R|_az = 0.27`、`|R|_el = 0.44`（0916 是 −139° / −144° / 0.70 / 0.31，**主次还互换了**）。
这**不是漂移证据** —— 换了阵面、接收机、还隔了三周，指纹本就该不同 ——
但它证明了一件更重要的事：**`phi_correction` 不是通用常数，它绑定具体硬件配置。**

### 7.4b ⚠ 跨 12 天的决定性实测（0928 vs 0916）：**φ 没动，`arg(R_dw)` 动了 96°**

`F:\0928\RX\姿态\{177..181}.mat`（2026-09-28，五航线）与 `E:\0916` 同配置
（`fs`/`fc`=9.5 GHz/`PRI`=1024/30M_64），隔 12 天，直接回答了 7.4 末尾那个"没数据可测"的问题。

**先证通道口径相同**（用目标数据、与直达波无关）：原始 `ch2` 随航向有 −0.030/° 的斜率，
`ch1` 跨 4° 恒为 0.053 且无斜率 ⇒ `ch2` = 方位差口，与 0916 拆机结论一致。
（注意 `F:\tmp\boresight\out\rd_*.mat` 里 `RDdaz` 装的其实是 ch1、`RDdel` 装的才是 ch2，是旧命名的遗留。）

| | 0916 | 0928 | 差 |
| --- | --- | --- | --- |
| **`φ_az`（真值反查）** | ≈ **−93.5°** | ≈ **−104.6°** | **≈ 11°（未漂移）** |
| `arg(R_dw)_az` | −138.8° | **−42.9°** | **96°** |
| `abs(R_dw)_az` | 0.70 | 0.31 | 2.3× |
| `arg(R_dw)_el` | −143.9° | −141.7° | 2° |

0928 用自身真值扫 φ 的读数：φ=−114° → 96.4%、φ=−96° → 96.7%、φ=−90° → 96.4%
（96.4% 以上覆盖 **[−168°, −84°]**）；而 **φ=0° → 18.8%、φ=+2° → 14.5%**。

**两条结论：**
1. **`phi_correction` 是"每次会话"的量，不是常数。** 0916 为 +45°，0928 反推为 −51…−62°，
   变化 ~96~107°，**恰等于 `arg(R_dw)_az` 的变化**。就这个量而言，"每次都要重测"是对的。
2. **但 `φ` 本身跨 12 天没动，而 `φ` 才是真正要用的量 ⇒ 不需要直达波，硬编码 φ 即可。**
   代价是：`use_dw_phi=true` 配一个过期的 `phi_correction`，会**自信地输出 φ=+2.1°**
   （同号率 14.5%，近乎全错）。这个失效模式此前只是理论担忧，现在是**已实测**。

**适用范围仍待确认**（硬件事实，需问用户）：`E:\0916` 与 `F:\0928` 是同一台机器吗？
若是 ⇒ 上表是硬结论；若不是（同批次不同台）⇒ 退化为"φ 批次稳定（印证厂商第 1 条）、
`arg(R_dw)` 逐台不同"。**两种解读下 `use_dw_phi` 的取舍结论相同**，故不阻塞决策。

### 7.5 那么"每次数据都要重测"吗？—— 不必，但自检必须留

两条路其实**都被同一个自检兜住**：

| 姿态 | 静默失效模式 | 谁能发现 |
| --- | --- | --- |
| 硬编码 φ | φ 漂了 | `sign_selfcheck`（批后报警） |
| `use_dw_phi = true` | `phi_correction` 过期；或漂移在漏泄**注入点上游** | 同一个 `sign_selfcheck` |

所以**自检是必需品，φ 的来源是可选项** —— 两种姿态不是谁更安全，而是**互换了失效模式**。

据此的取舍（§7.4b 的实测让第一条从"倾向"变成"确定"）：
- 默认 **硬编码 φ**（`cfg.angle.use_dw_phi = false`）+ 保留自检。零标定负担，自检在每次批处理都免费跑。
- `use_dw_phi` 已实现并默认关闭，自检一旦报 `warn`/`fail`，改一行即可启用。
- ~~若某航次不可重飞，可预先打开 `use_dw_phi` 当保险~~ —— **实测不支持这么做**：
  `φ` 稳定而 `arg(R_dw)` 不稳定，常开等于**把稳定量换成不稳定量**。
  只有在**当前会话刚重标过** `phi_correction` 时才值得打开。

### 7.6 换批次/换会话的 φ 标定口径

既然 `φ` 稳定而 `phi_correction` 不稳，标定对象应是 **`φ` 本身**，不是直达波：
取一条**已知几何**的航线，在 ROI 内（`|δ_true|` ≤ 5°）扫 `φ ∈ [−180°, 180°]`，
找同号率最高的平台取中心。**必须分侧别留样本**（本批 177/178 在负侧、179/180/181 在正侧，
跨视轴 178.7° 才成立）；只有单侧样本时该法退化。
0928 实测最大 97.0%（不到 100% 是因为航线 179 的 `ψ=+0.29°`、`|Δ/Σ|` 仅 0.036，
几乎压在视轴上，这些帧的侧别本身由噪声决定）。

## 9. 一句话总结

> 单脉冲的理想复比值 `Δ/Σ = i·tan(βδ)` 是**纯虚数**，侧别信息全在虚轴上；接收链路把它整体旋转了 `φ_chain`。原代码取实部，等于往"本来就恒为零"的那根轴上投影，于是符号由一个只剩 6% 的残差决定。**修法是把投影方向转到 `φ` 上（`sign(Re(c·e^(−iφ)))`）**——`sign(Re(·))` 等价于假设 `φ=0`，而这个假设在 0916 那批上恰好越过了 90° 边界。
>
> 注意"`φ` 必须**标定**"不等于"`φ` 必须**每批在线测**"：`φ` 由硬件决定（厂商：同批次恒定、随频率变），实测跨 12 天只动 11°，而容差是 90°，所以**按批次固定即可**；需要在线跟踪的是 `phi_correction` 而不是 `φ`，而后者已被证明不稳定（见 §7.4b）。"加一个固定偏角"之所以不行，是因为它靠的是"恰好离边界还有几度"的运气，没有标定依据。
>
> 落地口径：`φ` 按批次硬编码（0916 与 0928 两次独立测量都落在 **−93 ~ −105°**），**`sign_selfcheck` 每次批处理免费跑并报警**。
