# 单通道 RawIQFrame 接收与输出

[总览](../README.md) · [规格](../SPEC.md) · [控制表](../pcie/control-protocol.md)

## 分工

- `options.hpp`：选路、时长、有界队列及配置/日志路径；所有参数先于设备访问校验。
- `pcie_receiver.*` / `iq_decode.hpp`：复用四 Lane→八通道映射，只解码所选通道。控制表返回原始 TX/RX，IQ 返回拥有存储的样本；双快照不一致和无效描述字以 gap 报告。
- `raw_assembler.hpp`：控制表先于该硬件帧的 IQ，收齐 8192 点即完成一帧。可以跨描述字，不跨控制表拼接。
- `raw_iq.hpp`：内部拥有型块及验收用 FNV-1a64 业务指纹；不是第二套线格式。
- `raw_output.hpp`：一个输出线程、一个有界队列，使用 SDK `try_create` 和 `write`。
- `main.cpp`：接收循环、诊断日志、组帧、故障及退出管理。

## 配对与单通道约束

依据既有 RTL 的 control→第 1 段→第 2 段顺序组帧；不从 IQ 数值扫描 K 字符，不识别脉冲/CPI。TX 全 F 合法，时间戳数值不换算或改写。

首次有效控制之前的 IQ 计入 `startup_samples`，不伪造配对；正常停止时未满帧的尾部记入 `tail_samples`。开始收帧后，提前到达控制表、超过 8192 点、未见新控制又收到 IQ、无效包或双快照不一致都会失败，不重新拼接缺口两侧数据。

当前每个输出块 Metadata 为通道数 1、采样点数 8192。实际所选 `0..7` 编号保留在日志，不冒充矩阵行号或增加业务字段。原有 `cpi_*` 帮助代码/测试仅保留历史检查用途，正式入口不包含、不加载这些模板。

## 所有权、背压与退出

接收线程不等待 SDK 输出；排队的是独立样本存储，不是 DMA 指针。队列默认 512 帧，容量包含输出线程持有的在途块；另有一个正在组装的帧及有界接收快照。满队列明确报错，不覆盖、不静默丢新帧、不自动恢复。

Output 打开端口最多 3 秒，故障发生在硬件初始化之前。输出线程遇 Ring 满会短暂重试，主线程仍接收；持续阻塞最多 5 秒。正常结束给整个排空阶段 5 秒，不按每个帧无限延长；异常析构取消等待并 join。DMA 协作线程先停止，再解除映射。

Sidecar 原有断链策略可能丢完整帧，本次不重写传输层。必须将 Source 提交总数、Envelope 帧序、Sink 保存数量及业务指纹共同核对；断链后不能宣称自动无损恢复。Source 的成功退出不等于文件保存成功。

## 诊断与证明边界

原有 RX 差值诊断继续记录异常，不改写 IQ/时间戳；有异常的会话不能通过无损验收。`business_fnv1a64` 覆盖按固定顺序表达的四个业务字段及全部 CS16 字节，供正常非对抗链路对照，**不是密码学认证、完整裸帧 SHA-256 或硬件连续性证明**。

`integrity_verified=false`、`hardware_loss_count=unknown` 保持诚实：双快照相同不证明 DMA 所有权；SDK 序号也不等于硬件采样序号。新 PCIe 描述字配对仍需发布候选后的真实硬件验收。
