# QSFP1 / Quad129 控制表与 RX 时间戳校验

[底层接收](README.md) · [Worker](../src/README.md)

本文以用户最新 RTL 协议为准，替代此前带 `frame_sequence`、W0 标识字和脉冲长度数组的版本。旧序号实测仅作为当时版本的历史记录保留，不能用于解释本版时间戳。

## 控制表：两个 64 位时间戳

控制表共 6 个 32 位字、24 字节。每个字在四条 Lane 上广播，PCIe 控制载荷按保留 `CTRL_HEAD` 的布局读取。当前只提取时间戳，不校验表头、表尾或其他业务字段；至少需要 20 字节才能安全读完 RX 时间戳。

| 字节偏移 | 内容 |
| --- | --- |
| 0 | `CTRL_HEAD = 0xAAAA5555` |
| 4 | `tx_start[31:0]` |
| 8 | `tx_start[63:32]` |
| 12 | `rx_first[31:0]` |
| 16 | `rx_first[63:32]` |
| 20 | `CTRL_TAIL = 0xAA5555AA` |

按小端 32 位字组装 `timestamp = (uint64_t(high) << 32) | low`。未发射时 `tx_start=0xFFFFFFFFFFFFFFFF`，这不是错误；TX 时间戳不参与校验，保留在诊断记录中。

本版**没有 frame_sequence**。字节偏移 8 是 TX 时间戳高字，不能再按帧序号解释或要求递增 1。

## RX 时间戳校验与记录

默认对每个有效控制载荷的 `rx_first` 检查，不再使用旧 `--check-frame-sequence` 开关：

1. 第一帧只建立基线，不要求从 0 或 1 开始。
2. 此后每帧计算 `delta = uint64_t(current_rx - previous_rx)`，以模 2^64 算术处理回绕。用户最新指定预期值为 **98304**，不再使用 8192。每硬件帧仍为 8192 个采样点，不把样本点数直接当作时间戳计数。
3. `delta != 98304` 时保存全部异常，不只保留前 16 个样例。重复时间戳、前跳、回退/复位均按实际差值记录，不将差值自动换算成 IQ 丢包数。
4. 无论比较结果如何，下一个基线都更新为当前有效控制帧，从而比较的是连续收到的两帧，不跨过异常帧追溯旧基线。
5. 异常只用于诊断和检查结果，不触发 IQ 丢弃、组帧重置、样本填零或重新编号；有异常的会话不能通过无损验收。短控制载荷无法安全读取时仍按无效包处理，并清除时间戳基线；新 RawIQFrame 路径将这种 gap 作为会话失败，不跨不可读控制帧拼接。

通过 `--timestamp-errors PATH` 指定追加写入的 JSONL 文件，默认 `rx_timestamp_errors.jsonl`。每次运行写独立会话标识；每条异常记录包含前后 RX/TX 时间戳、实际差值、预期差值、控制包和描述字计数、DMA 偏移/长度/有效掩码、所选通道及单调时钟时间。64 位值按字符串保存，避免 JSON 消费者丢失整数精度。

日志文件在打开、写入或刷新失败时明确报错，不静默漏记。Docker 运行时应把日志目录挂载到宿主机，避免 `--rm` 删除诊断文件。文件为缓冲顺序写入，不为每个控制包输出高频终端日志；退出和周期性报告时刷新。异常量大时日志会持续增长，需要给本次检查预留磁盘空间；不自动覆盖或抽样丢弃异常。

至少观察到两帧且全部差值为 98304，才报告 RX 时间戳校验通过。提取、日志和比较都使用原始 64 位值，不先除以 12 或四舍五入。该检查不证明 DMA 复制期间没有覆盖，也不能据此直接认定缺口发生在硬件哪一层。

## 链路与帧布局

- 四条 Lane，各 4.8 Gb/s、8b/10b，用户时钟约 120 MHz。
- 每个用户拍合计 128 bit，每 Lane 32 bit。
- CH00～CH07 每通道 30.72 MS/s；每硬件帧每通道 8192 点，分两个 4096 点段，**不是两个雷达脉冲**。
- SOF 到 EOF 共 17103 拍，发送约 142.525 μs；8192 点采集约 266.667 μs。
- 下面除 IQ 外，每个字在四 Lane 广播。K=`0001` 表示每 Lane 仅最低字节为 K 字符，K=`0000` 表示普通数据。

| 拍号 | 内容 | 每 Lane 字 / K |
| --- | --- | --- |
| 0 | SOF | `B5B5151C` / `0001` |
| 1～64 | IDLE ×64 | `B5B595BC` / `0001` |
| 65 | CTRL_HEAD | `AAAA5555` / `0000` |
| 66～67 | TX 低字、高字 | 时间戳 / `0000` |
| 68～69 | RX 低字、高字 | 时间戳 / `0000` |
| 70 | CTRL_TAIL | `AA5555AA` / `0000` |
| 71～134 | IDLE ×64 | `B5B595BC` / `0001` |
| 135 | CTRL_END | `B5B5351C` / `0001` |
| 136～199 | IDLE ×64 | `B5B595BC` / `0001` |
| 200 | 第 1 段 GAP | `B5B5153C` / `0001` |
| 201～264 | IDLE ×64 | `B5B595BC` / `0001` |
| 265 | 第 1 段 START | `B5B5353C` / `0001` |
| 266～329 | IDLE ×64 | `B5B595BC` / `0001` |
| 330～8521 | 第 1 段 IQ，4096 点 ×2 拍 | 通道数据 / `0000` |
| 8522～8585 | IDLE ×64 | `B5B595BC` / `0001` |
| 8586 | 第 1 段 END | `B5B5553C` / `0001` |
| 8587～8650 | IDLE ×64 | `B5B595BC` / `0001` |
| 8651 | 第 2 段 GAP | `B5B5153C` / `0001` |
| 8652～8715 | IDLE ×64 | `B5B595BC` / `0001` |
| 8716 | 第 2 段 START | `B5B5353C` / `0001` |
| 8717～8780 | IDLE ×64 | `B5B595BC` / `0001` |
| 8781～16972 | 第 2 段 IQ，4096 点 ×2 拍 | 通道数据 / `0000` |
| 16973～17036 | IDLE ×64 | `B5B595BC` / `0001` |
| 17037 | 第 2 段 END | `B5B5553C` / `0001` |
| 17038～17101 | IDLE ×64 | `B5B595BC` / `0001` |
| 17102 | EOF | `B5B5551C` / `0001` |

无完整帧待发送时持续 IDLE，帧间 IDLE 数不固定；原始光口接收应依据 SOF 而非固定间隔寻找下一帧。当前 Worker 使用接收 FPGA 已分类的 PCIe 描述字，不在 IQ 样本中按数值扫描 K 字符，也没有独立可见的 SOF/EOF 标记。新 RawIQFrame 路径按控制表及随后共 8192 点的 IQ 组帧；提前控制、超长或无新控制的后续 IQ 均报错。PCIe 描述字与该顺序的真实硬件对应仍需验收。

## 与 RawIQFrame 的边界

当前输出改为独立 `RawIQFrame 4:1`，只带所选单通道 IQ、两个原始时间戳和矩阵维度；不再组 751206 点软件 CPI，不加载 signalsource 雷达模板。两个硬件段仍不解释成脉冲。旧 IQ 1:3 契约不变，历史 CPI 相关诊断记录仅作旧版证据。

真实 IQ 的每 Lane 两拍通道排列继续沿用既有接收适配器。双快照及帧长度检查不证明 DMA 所有权或 ADC 连续；禁止以“已收齐 8192 点”冒充所有硬件完整性关卡通过。
