## 光口控制表

最新版 QSFP1 / Quad129 格式见 [control-protocol.md](control-protocol.md)。控制表不再含帧序号：偏移 4/8 为 TX 低/高字，偏移 12/16 为 RX 低/高字。TX 全 F 不报错；按用户最新要求，默认检查相邻 RX 时间戳模 2^64 差值为 98304，异常逐条保存但不清空软件 CPI。只读取第一根光纤的广播控制表，不新增表头/表尾业务校验，保留 DMA 边界与至少 20 字节的安全检查。

## 8 路布局

本次采用现有“4 根光纤 × 每根 2 路 IQ”的实现，不扩展到 16 路。`src[16]` 仍是底层光纤地址槽数组，不是逻辑 IQ 通道数。底层同步解析使用 8 位光纤有效掩码，循环上限为 `MPO_MAX_NUM=8`；接收映射为 1536 MiB，单光纤区间为 192 MiB。

沿用相邻 `pcie_device_handle.cpp` 中 `reassemble_pcie_iq_packet()` 的映射：

| 光纤索引 | 两个交织 CS16 样本对应的逻辑通道 |
| --- | --- |
| 0 | 0、1 |
| 1 | 4、5 |
| 2 | 2、6 |
| 3 | 3、7 |

对每根光纤，时刻 `t` 的两路复数样本分别位于 `src[pipe][2*t]` 和 `src[pipe][2*t+1]`。复用的 `CS16` 定义位于来源设备目录的 `include/cycore/device/i_device_stream.h`：先 `int16_t i`，再 `int16_t q`，每个复数 4 字节。因此每根光纤每个时间点占 8 字节，`tsize` 必须为 8 的正整数倍。

接收同步数据要求 `groupId=0`、前四根光纤有效位均存在且指针非空；`flag=1` 的控制表单独处理。Worker 逻辑通道编号不能直接使用旧接口的 `iChainNum`。

> [!NOTE]
> 以上是已查到的代码解释规则，仍需在目标板卡上验证。旧适配器直接按本机 CS16 读取，没有字节序转换；迁移部署需验证目标数据端序，输出统一为 SDK 要求的小端 CS16，不把本机解释方式当作通用硬件保证。

## 审查结论与实施调整

- 旧 `bslFiberRecvMain → xdmaDrvRecv → parseSyncQueue → XdmaDataQueue → bslFiberRecvGetInputData` 传递裸 DMA 指针。队列计数存在无锁读；同步覆盖出队检查仅检查光纤 0；未提供硬件消费者 ACK/租约，不能证明复制期间未覆盖。
- 旧配置加载使用无界文件读取，部分 mmap 失败检查及资源清理不完整。不能原样迁移这些缺陷。
- 独立采集阶段收敛为 `xdma_rx.h/c` 与 `devmem_io.h/c`：复用原物理地址、描述字位域和配置写入顺序。主线程轮询后立即复制，不保留旧裸指针队列。性能优化增加一个协作复制线程，按同一包的两半并行读取，每半仍双读取；全部完成才返回。这样减少宿主排队过期风险，但不等于硬件授予了所有权，也没有修改 MMIO/DMA 映射属性。
- `cJSON.h/c` 从原目录保留许可迁移，复用于参数模板解析；BIT 首版只分类计数，不解读日志或将其当成 IQ。无需迁移旧日志框架。
- 可对选中通道做两次复制比对，发现变化则丢弃部分 CPI；两次相同仍不能排除稳定的陈旧覆盖。日志必须标记 `integrity_verified=false`。
- **正式 SDK 输出受阻**：没有硬件连续性/覆盖保护的充分证据，不把此采集检查路径直接用于保证完整性的正式输出。独立检查仅证明收到可解析数据及软件分块长度。

## 迁移边界

- 迁移接收必需的寄存器配置、内存映射、描述字解析、队列及设备状态处理。
- 接收层持续消费全部输入描述信息，不能因只选一路而停止处理其他输入。
- 以 C 源码构建为主，不依赖预编译库或开发机绝对路径。
- 统一旧 `include/` 与 `src/` 中重复的头文件，只引入接收必需依赖。
- 不迁移为本次业务服务的硬件 TX 路径：`bslFiberRecvDataSend()`、发送 BAR 线程及 TX 缓冲均不属于下游 Worker 转发。
- 软件 CPI 分块（每帧 751206 点）、signalsource 模板 Metadata 和 SDK 输出留在 [src/](../src/README.md)，不放入底层库。

## 接收安全与所有权

`inputmsg.src[]` 指向会被硬件循环覆盖的映射内存。描述信息出队不代表获得 DMA 区域的永久所有权；不能长期缓存这些指针，也不能直接交给 Sidecar。

迁移时必须检查：

1. 描述字类型、有效位、指针、长度、对齐及映射范围。
2. 所用光纤的覆盖状态，以及复制期间的数据一致性。旧覆盖判断不是完整的 DMA 所有权保证，需结合硬件协议确定可验证的保护机制。
3. 队列索引及并发访问、初始化失败清理、停止和重启时的资源释放。
4. 无数据与设备错误的区别，错误向 Worker 可见，不静默发送损坏数据。

解除映射前必须保证没有消费线程继续访问其地址，具体停止顺序见 [Worker 生命周期](../src/README.md#缓冲背压与退出)。

硬件物理地址及 `/dev/mem` 权限的部署限制见 [板卡配置](../pcie_config/README.md#运行安全)。
