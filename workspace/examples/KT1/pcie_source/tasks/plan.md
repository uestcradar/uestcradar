# RawIQFrame 单通道输出实施计划

[规格](../SPEC.md) · [任务清单](todo.md)

用户已批准本计划，协议名称改为 RawIQFrame。执行顺序：P1 → P2 → P3 → P4 → P5 → P6；各阶段记录真实证据，不把实现、离线检查、原生测试与服务器硬件验收混为一项完成。

## P1：SDK 契约

新增 RawIQFrame 4:1：两个原始 uint64 时间戳、两个 uint32 矩阵维度、CS16 数据。仅 data.h、contracts/raw_iq.json、contract_catalog.def、契约测试四处新增。沿用代码生成机制，旧 IQ/PC/RD 不变。黄金字节、动态矩阵及错误输入回归通过。

## P2：SDK 可退出输出

单独补充 Output<T>::try_create(metadata)：仅 Ring 满时返回空；关闭/损坏及错误参数抛错；一个有效输出租约；失败不泄漏预留槽、不因重试制造帧序号缺口。旧 create/write 与 parent trace API 保持兼容。测试满 Ring、释放后重试、取消租约、关闭及错误输入。实施时发现旧端口构造在 SHM 缺失/未初始化时无界等待，补充可选打开超时重载，新 Source 使用 3 秒；保留旧默认语义及 Ring ABI，并增加对应回归。

## P3：仿真到裸帧文件

在 signalsource 提供独立 RawIQFrame 入口和明确契约的镜像变体，不改旧入口及算法链。单通道确定性 IQ/TX/RX，有限帧数及受控速率，能在背压下退出。使用真实 Sidecar 和未修改的 SignalSink；录制先启动、发送有限帧、等待排空后同步结束。离线检查业务字节、帧序和数量，损坏/截断必须拒绝。

## P4：PCIe 单通道

复用选路/双快照，读取原始控制时间戳，并验证 control → IQ 数据段 → 下一控制的分组关系。独立硬件帧组装（当前 8192 点/通道），遇不完整/超长/错误配对明确失败。只输出所选一路，移除正式输出对 CPI 模板的依赖。硬件顺序未验证时不得拿最近时间戳猜配对。

## P5：背压与生命周期

采集与输出隔离，有界完整帧队列；复制后的样本由帧拥有。复用 try_create，在缓冲满、下游断开、停止请求等场景中可退出；溢出明确失败，不静默丢帧或自动续录。单元/进程测试覆盖队列与停机，保留接收异常诊断。

## P6：原生服务器验收

原生 ARM 构建与测试；按现有 Harbor 固定 digest 规范交付。不覆盖原 Web。先仿真闭环，再真实选中通道 10 秒冒烟、60 秒完整录制；记录接收状态、提交/保存帧数、业务摘要、镜像身份、文件同步及存储测量。隔离的 TCP 诊断不冒充 Web strict-RDMA 验收。

60 秒有限会话完成与长期稳态写入分开判定。当前磁盘可能不足以长期承受约 123 MB/s 的单通道输入；不足时如实标记，不降采样、不改 SignalSink、不以缓存或八通道指标替代真实结果。

## 不变部分

SignalSink src/、USINK001 格式、SDK RawFrame 输入、公共 Envelope/Ring ABI、旧契约、旧算法链、Web/Frontend 功能、硬件配置和系统全局设置。

旧软件 CPI/模板迁移的历史证据与 TODO 保留在 git 和任务清单历史区，不再作为本次正式输出要求。
