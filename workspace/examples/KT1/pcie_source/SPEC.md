# RawIQFrame 单通道采集与裸帧保存

状态：用户已批准实施。新协议名称为 `RawIQFrame`；本文件取代旧计划中 IQ 1:3、751206 点软件 CPI、雷达模板及允许丢 CPI 的正式输出目标。旧 SDK IQ/PC/RD 契约和旧算法链不变。

## 目标与边界

在原生 ARM 服务器完成 PCIe Source 所选单通道 → Sidecar → Sidecar → SignalSink → 文件。先用确定性仿真 SignalSource 验证同一链路，再替换为 PCIe Source。只接收，不新增硬件 TX 功能。

SignalSink 继续保存完整 Envelope/Metadata/Payload 裸字节，现有 USINK001 文件格式、写入、同步及失败策略均不修改。只调整部署的具体输入类型、目录和资源配置。

不接算法，不实现多通道输出、波形解释、新 Web/Frontend 功能、压缩、降采样或自动删除录制文件。不改变 MMIO 地址、固件、硬件寄存器配置顺序、系统 VM/调度/文件系统设置。

## 契约

新增 `RawIQFrame` / `RawIQMetadata`，独立类型 4:1（当前目录 1/2/3 已占用），复用现有 64 字节 Envelope。业务 Metadata 为 24 字节，小端：

| 字段 | 类型 | 偏移 |
| --- | --- | --- |
| tx_timestamp | uint64 | 0 |
| rx_timestamp | uint64 | 8 |
| channel_count | uint32 | 16 |
| samples_per_channel | uint32 | 20 |

Payload 从 Metadata 后紧接 CS16 矩阵：行=通道，列=每通道采样点；每个样本 int16 I 后接 int16 Q，沿用现有排列。维度可变，必须非零，校验乘法溢出及实际长度。时间戳原值透传，包括 TX 全 F，不换算或假定单位。Envelope 时间戳仍是框架字段，不替代业务 TX/RX。

PCIe Source 使用 `--channel 0..7`，默认 0，每帧 channel_count 必须为 1。通道选择记入运行日志而非新增业务字段。新协议通过 SDK data.h、JSON、catalog、契约测试四处新增，生成物自动生成。

## 接收及输出

复用已验证的选路、双快照及边界检查。按控制表及两个采样段组织单通道硬件帧（当前协议每帧 8192 点），不依赖软件 CPI 或离线模板。验证 PCIe 描述字与协议顺序，配对不明确不能采用“最近的时间戳”猜测输出。启动未对齐的数据不算已接受完整帧，必须计数；运行中的缺口、不完整/超长帧、无效控制或快照不一致明确失败，不能补零或跨缺口拼接。

硬件控制异常保留诊断；时间戳数值本身不被改写。无损验收要求可检测异常为零，不把时间戳差值换算为硬件丢样本数。

采集和 SDK 输出之间内存有界，持有独立完整帧。SDK 增加非阻塞输出获取以支持取消，并增加可选打开超时，同时覆盖 SHM 尚不存在和头部尚未初始化的等待；新 Source 使用 3 秒上限。底层只增加函数重载，不改 Ring 布局/ABI。旧默认构造和 create/write 行为保持兼容。队列满、下游故障不静默丢帧，不自动恢复成成功会话。停止可控，不强杀线程，不在后台线程仍读 DMA 时解除映射。

## 验证与成功条件

1. SDK 黄金字节、双时间戳、动态矩阵、非法长度/溢出、try_create 满/空/故障/租约测试，以及旧契约回归通过。
2. 确定性单通道仿真经真实 Sidecar 与未修改的 SignalSink 落盘，逐字节核对业务数据和记录顺序；截断或损坏不能伪装完整录制。
3. 原生 ARM 真实硬件：10 秒冒烟，60 秒初验；记录固定镜像身份、设备/选路、Source 交付量、Sink 保存量、完整性摘要及所有接收/输出故障计数。控制录制窗口并排空在途帧后停止 SignalSink，等待文件同步完成。
4. 正常会话文件可完整读取；业务字节、数量及顺序一致；选中通道以外不输出；无可检测覆盖、缺口、队列溢出或静默丢弃。人为背压/断链/停止检查不挂死，失败明确报告。
5. 文件完整性、Source 到文件一致性、硬件连续性、稳态存储带宽分别报告。双快照一致不证明 DMA 所有权；未知硬件漏采不可宣称不存在。

60 秒文件完整保存（含结束后的同步等待）不等于无限时长持续录制达标。历史单通道约 30.7 MS/s、CS16 约 123 MB/s；现有盘长写约 101 MB/s。按本轮真实速率验收，存储不足明确阻塞，不套用八通道压力指标。
