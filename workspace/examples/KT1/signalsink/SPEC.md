# SignalSink 需求

**我的需求：**新增独立 SignalSink，作为基础设施中的通用数据接收与保存组件。只要上游满足框架裸帧协议及接入契约，无论是 IQ、脉压（PC）、RD 还是自定义数据，都能持续接收并流盘，完整保留帧边界、帧头、Metadata、Payload 和接收顺序，供后续离线分析及回放。原始 IQ 目标输入为 8 通道、每通道 15.36 MHz、每个复数采样点 32 bit，合计 491.52 MB/s，约 29.49 GB/分钟，不含帧头和存储开销；其他类型按实际载荷计算吞吐。若检测到或无法避免录制不连续，应立即停止本次录制并明确报错，不允许静默丢帧后继续拼接。单机与服务器使用同一组件，保存默认关闭，不根据启动位置或是否由 uestcweb 启动自动判断；需要录制时显式开启，关闭保存仍正常消费输入。SignalSink 随全局数据流运行，录制独立起停；Web 确认节点为 SignalSink 后，在节点详情抽屉的“输入 / 输出实时预览”区域保留输入波形，将原“输出波形 / 输出 RD 图”卡片位置替换为保存控件，提供开始录制、停止录制、录制状态、待写缓冲队列水位和目标磁盘容量水位。不修改拓扑节点卡片的 Upstream / Downstream 槽位水位条，也不将保存控件放在抽屉下方的 downstream 链路详情表中。其他节点维持原界面。保存位置应可指定且持久保留，不静默覆盖已有文件。本需求不包含算法处理、MAT 转换或中间节点旁路录制。

**待确认项：**异常时是否仅停止录制、继续消费输入，还是停止节点或整条链路；连续性判据及上游需要提供的采样序号、时间戳或缺口标记，不能将裸帧完整等同于采样连续；当前 pcie_source 为八路选一路，八通道同时输出的改造范围与数据布局需确认；目标录制时长、容量、有限帧数或时长录制、文件滚动及容量用尽后的处理方式；磁盘满或写入失败后的收尾行为，以及异常退出或断电允许损失的数据范围；是否需要同一录制会话混合不同类型或版本的帧；SignalSink 节点的可靠识别方式，以及队列和磁盘水位的告警、停止阈值。

## 保存控件草稿

位置：**节点详情抽屉 → 输入 / 输出实时预览 → 原输出波形卡片**。输入预览和实际存在的链路详情保持原有功能；SignalSink 无输出，不再显示输出波形占位卡片。以下为录制中示例，数值仅供展示。

[打开 HTML 控件草稿](recording-control-prototype.html)（浏览器直接打开；静态示意，不连接后端）。

- **待写缓冲队列水位**：已占用容量 / 总容量，表示待写入磁盘的录制数据积压；与原有 Upstream Ring 水位分开展示，不复用输入 Ring 指标冒充录制队列水位。
- **硬盘水位**：实际保存目录所在存储卷的已用容量 / 总容量，并显示当前进程可用空间；不是本次文件大小或磁盘带宽利用率。
- **抽屉行为**：关闭抽屉只结束界面展示，不停止已开始的录制；重新打开时展示节点当前实际录制状态。
- **按钮和状态**：待命时允许开始；录制时允许停止；启动中、收尾中禁止重复操作。普通停止录制不退出 SignalSink，继续消费输入。状态以节点确认结果为准，不以点击按钮即视为成功。
- **异常展示**：显示“录制失败：队列溢出风险 / 数据不连续 / 磁盘满 / 写入失败”等实际原因，不自动续录。离线或遥测过期显示“状态未知”，水位显示“未上报”，禁用操作，不冒充 0%。
