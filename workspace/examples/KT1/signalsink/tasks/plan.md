# SignalSink 实施计划

依据：[SPEC](../SPEC.md)。状态：**待审阅的计划；本轮止于 [Todo](todo.md)，不执行实现。**

## 1. 只做一条最小闭环

先解决受支持的裸帧接入，再做“本地开始 → 原样写盘 → 本地停止并校验”，最后接 Web 的专用按钮。不先造通用控件框架，不让预览成为录制依赖。

实现面只有两处：本目录的 SignalSink，以及现有 Web 的专用适配。SDK 裸帧入口是需批准的前置扩展，不以节省文件为由绕过它。Frontend、Sidecar、Ring 传输布局、既有算法默认不改。

## 2. 最小技术方案

### Worker

- 一个接收进程，接收侧取得完整帧并验证后复制到有界队列，及时释放输入 lease；一个顺序写入线程负责文件和收尾。不先做零拷贝持有 Ring Slot、异步 IO 框架或线程池。
- 帧所有权、开始/截止边界及状态由一个明确的同步点管理。状态锁不跨磁盘 IO，读取状态不能阻塞接收循环。
- 同一个可执行文件提供 `control status/start/stop` 客户端模式。建议用容器私有 Unix socket 与主进程通信，权限仅允许运行用户；不开放网络监听，不挂 Docker Socket。
- socket 请求有长度、超时及操作白名单；开始只提交一次状态转换，停止只指定录制 ID。实现内部通信即可，不设计通用 RPC 协议或扩展注册表。
- 一会话一文件、排他创建、有界内存、明确失败；不滚动、不压缩、不自动恢复。单独的小校验程序确认原始字节与完整前缀，不发展成回放器。

以上控制方案按 D6 待确认；D1–D5 决定失败行为、接入和文件完成条件。

### Web

- 建议仅增加 SignalSink 专用入口：`GET /api/v1/orchestration/signalsink/status?ip=...`、`POST /api/v1/orchestration/signalsink/start`、`POST /api/v1/orchestration/signalsink/stop`。
- 开始请求只需节点 IP、相对保存目录；停止请求需节点 IP 和录制 ID。不接受任意命令、容器 ID、URL 或宿主挂载路径。
- 入口复用现有会话、授权、CSRF、SSH 指纹及命令转义。仅操作已检查节点上实际运行、身份匹配且唯一的目标 Worker；选择列表中的镜像不等于它正在运行。
- SSH 只执行固定 `docker exec` 控制命令，返回有界 JSON。现有 `runSSHOutput` 没有完整请求期限，不能原样拿来做无限等待的轮询；为这些调用限定连接、执行时间和输出体积，取消请求时释放连接，不发送停止录制。
- 建议控制请求总期限 5 秒、状态响应上限 64 KiB；超时按“结果未知”处理。打开区域后每次查询结束再等约 1 秒，不积压；3 秒未拿到新状态就显示过期。具体限值在接口测试中固定。
- 新鲜度按浏览器收到状态后的经过时间计算，不依赖节点墙上时钟。采集计数跨 JSON 使用十进制字符串。
- 只加一个 `RecordingPanel` 和必要 API 调用。位于现有 iframe 外，保留现有节点页；关闭区域只取消查询，不触发 stop。短视口下不能把预览挤到不可用或重现原有双滚动布局问题。

### 部署

- SignalSink 必须有专用、可核验的组件标识。具体标识及通用输入的镜像契约在 D3 中确定，不冒称 worker/v2 已支持 `any`。
- 仅对已识别的 SignalSink，把上游具体类型绑定到其输入，并校验尺寸/容量；旧 Worker 仍精确匹配。若当前发布工具不能表达此契约，先批准最小适配，不能另建发布体系或跳过检查。
- 只给 SignalSink Worker 增加 `/captures` 持久挂载；Frontend 不挂录制卷。根目录由部署者明确配置，先核验存在性、权限与容量，不能隐式把整块宿主目录交给浏览器选择。
- 单机复用既有 TCP 模式，服务器 Web 部署保持 strict-RDMA；不恢复传输选择器，不自动降级。
- 必须复用既有 ARM 构建和 immutable Harbor 发布流程。原始 SDK 镜像未包含新接口时，需要先交付适配后的 SDK，不能假设当前固定 digest 自动获得能力。

## 4. 风险与止损

- **原样保存做不到**：SDK/契约未关闭就停在 T01，不以类型化重编码、复制私有帧定义或改名“raw”替代。
- **磁盘持续带宽不足**：真实存储连同收尾同步计时，报告队列趋势；降低承诺需用户决定，不能增大缓存掩盖长期写不动。
- **故障与连续性语义不清**：T00 固定规则和允许损失边界；测试分别说明帧保存、上游缺口和硬件采样，不能相互代替。
- **控制面开销**：只在抽屉打开时限频、合并同节点查询、限制输出；先测量，只有实测不合格才讨论新控制通道。
- **保存根目录风险**：不接受任意挂载，校验实际目标卷；ENOSPC 等异常保留失败文件，不自动清理用户数据。
- **回归或误部署**：其他 Worker、预览代理、安全边界和 IPC 做回归；真实服务器先确认空闲资源/可替换对象，保留前后容器身份记录。

本稿不填补 PCIe 八通道、Web 空节点首次安装 Worker、SDK 输出取消等其他项目的全部欠账；发现其中某项成为本功能必要前置时，明确记录阻塞，先审批范围再做。
