# Worker 入口、通道选择与软件 CPI

[返回总览](../README.md) · [底层接收](../pcie/README.md) · [验证计划](../tests/README.md)

> [!NOTE]
> 已实现接收检查、八路选路、模板加载及软件分块；`--capture-only` 可运行。本文 SDK 输出和背压队列仍为待实现目标，受硬件连续性及 SDK 等待取消机制阻塞。实际结果见 [验收记录](../tests/hardware-results.md)。

## 职责边界

Worker 负责配置校验、接收生命周期、选路、软件分块及 SDK 输出。硬件访问留在 `../pcie/`，网络传输复用 Sidecar，不引入 Cycore 的设备注册、流图或通用设备框架。

```text
底层描述信息与采样块
    → 校验、控制表/BIT 与 IQ 分流
    → 按现有映射解析 8 路 IQ，选择 channel
    → 积累 N 个单路样本，构造软件 CPI
    → 有界待发送队列
    → Output<IQFrame>::create / write
```

## 通道解析与选择

拟通过 `--channel 0..7` 选择逻辑 IQ 通道，默认 `0`；第 1 路对应索引 `0`。参数越界应在启动硬件前拒绝，首版不支持运行时切换。

沿用 [4 根光纤到 8 路 IQ 的映射](../pcie/README.md#8-路布局)，不能使用旧接口的 `iChainNum` 充当逻辑通道号。持续消费全部输入，校验四路光纤有效性，仅提取选中通道样本；不保留其他七路完整软件 CPI，不增加八个输出端口。

控制表按新版 [光口协议](../pcie/control-protocol.md) 提取 `tx_start` 与 `rx_first` 两个 64 位时间戳，不再读取 `frame_sequence`。TX 全 F 表示未发射，暂不校验；按用户最新要求，RX 相邻差值应为 98304，异常完整追加到 `--timestamp-errors PATH` 指定的 JSONL（默认 `rx_timestamp_errors.jsonl`），不因此丢弃 IQ 或清空软件 CPI。首帧只建基线，每帧比较后更新基线；保留最小 20 字节和 DMA 边界检查。BIT 只计数，控制表/BIT 都不作为 IQ 或真实 CPI 边界。

时间戳校验默认启用，旧 `--check-frame-sequence` 开关已删除。日志记录前后 RX/TX 值、差值、控制包/描述字计数、DMA 偏移/长度/掩码和单调时钟；全部异常保存，不限 16 条。打开、写入、周期刷新和正常关闭日志失败均报错；容器需挂载日志目录以便持久保存。退出码仍用于数据存在性/接收错误检查，时间戳结果单独看 `[timestamp-check] strict_continuous`，不把退出 0 当连续性通过。

## 软件 CPI 分块

硬件无法提供完整 CPI 边界，首版不等待真实脉冲或 CPI 同步：

1. 首版固定 `N=751206` 个复数采样点，`pulse_count=64`，与当前 `signalsource` 一致。不提供独立的任意分块尺寸或脉冲数覆盖；参数模板形状不匹配时在启动采集前拒绝。
2. 将连续 DMA 包中的选中通道样本拼接；每攒满 N 点生成一个软件 CPI。一包可以跨越多个输出帧。
3. 不修改真实 IQ 值，不补零，不按假 PRT 丢弃、重采样或制造样本。
4. 检测到丢包、覆盖或输入无效时丢弃尚未完成的块，从下一有效完整采样组重新积累，不拼接断裂两侧样本。
5. 停止时丢弃不足 N 点的尾块并计数，不发送半帧。

`cpi_index` 从 0 开始，为每个完成的软件 CPI 分配并递增；该帧使用 `CPI[cpi_index % 10]` 参数模板，将模板内的 `cpi_index` 替换为软件序号。包括因输出队列满而丢弃的完整帧，序号和模板轮转仍前进，不因丢帧回退。尚未成帧的数据丢失单独计数；该序号不是硬件 CPI 序号，也不保证体现所有采集缺口。

## SDK 输出与假 Metadata

参照 [signalsource](../../signalsource/README.md)，保持 [SDK IQFrame](../../../infra/sdk/README.md) 的 `type_id=1 / type_version=3` 不变。使用 `output.create(metadata)`，填充样本后调用 `output.write(std::move(frame))`。

- `channel_count=1`，`samples_per_channel=N`，Payload 为标准小端 `ComplexInt16`（`int16_t I, int16_t Q`）。
- `pulse_count=64`，其余 Metadata 和四组逐脉冲数组逐字段沿用 [signalsource 参数模板](../pcie_config/README.md#联调默认参数)，不另造 PRT、载频或缩放默认值。
- 只读取模板参数文件，不要求或读取 `input.bin`。采样值直接来自所选 PCIe 通道，不乘模板缩放因子；`dequantization_scale` 作为 Metadata 保留供下游使用。
- 下游通过 `frame.data()[0]` 读取选中通道；原始通道号记入配置和日志，不挪用 Metadata 字段。
- 启动日志明确记录 `synthetic_metadata=true`、选中通道、N 和全部生效参数。该标记仅在日志中，不修改帧结构。

> [!IMPORTANT]
> 这是对现有 CPI 契约的联调性使用：格式、形状及参数与 `signalsource` 对齐，但不代表真实采集时序。64 个脉冲及其时间参数只是模板信息，不表示在真实采样中识别出了 64 个脉冲。下游保持相同通信及输入适配，无需识别数据源类型；部署者仍需知道假参数模式。原离线样本哈希和精确算法结果校验不能用于实时数据，处理结果不作为真实雷达性能验证。

## 缓冲、背压与退出

- **线程**：主线程轮询、组帧、写诊断日志。`DmaSnapshot` 使用一个常驻协作线程，将大包分为两半并行复制到两份可复用普通内存快照；每半都独立读取两次，随后在主线程解码并比较选中通道。小于 4096 字节的包直接顺序双复制，避免唤醒开销。只有一包在处理，`copy()` 等待两半完成才返回，不排队裸 DMA 指针；解除映射前停止并 join 协作线程。
- **性能与等待**：仅无描述字时休眠，控制包/BIT 不算空闲。日志仍为缓冲同步写入；实测瓶颈在 DMA 读取，暂不增加日志线程或通用队列。最终 channel 0 的 30 秒检查约 30.693 MS/s、112400 次时间戳比较全部满足 98304，见 [性能实测](../tests/throughput-results.md)。正式 SDK 输出仍未实现，未来需单独隔离 SDK 背压。
- **所有权**：不长期保存或向 Sidecar 传递 DMA 指针，遵守 [底层接收约束](../pcie/README.md#接收安全与所有权)。
- **容量**：组帧和待发送队列有固定上限、明确所有权；不承诺 FPGA 到下游全链路零拷贝。
- **过载**：采用下述整帧丢弃策略。SDK 背压不等于硬件停流，也不允许背压改变采样切分边界。
- **退出**：停止采集消费并等待结束，再停止底层接收线程及解除映射；输出等待必须可取消，随后释放队列及 SDK 资源。

至少记录接收包、控制表、无效包、硬件/队列丢包、覆盖、丢弃完整帧、丢弃尾块/部分块、输出帧计数及选中通道。无数据等待与设备错误分开处理。

## 整帧丢弃策略

**允许少发整个 CPI，不允许发送残缺、被覆盖或跨采集缺口拼接的 CPI。** 此处完整指一个软件 CPI 含选中通道连续的 `751206` 个有效复数样本，不代表已识别真实硬件 CPI。

1. **先完成切分，再决定发送或丢弃**：采集线程持续消费数据，独立于下游水位，每 N 点完成一帧。不能因输出满而跳过任意 DMA 包或任意数量样本，导致后续切分边界移动。
2. **背压处理位置**：下游满会经 Sidecar/输出 SHM 使输出线程等待；采集线程不等待 SDK 写出。它继续组帧，待本地有界待发送队列也满时，丢弃新完成的整个 CPI，不淘汰半帧、不覆盖输出线程持有的帧。
3. **满时继续完整计数**：即使缓冲一直满，每个被丢弃的 CPI 仍对应连续 N 点；完成后软件序号和模板轮转照常前进。恢复空间后从下一完整 CPI 入队，不发送之前被丢弃帧的剩余部分，不重编号掩盖丢帧。
4. **所有权与提交**：组帧缓冲、排队帧和正在发送的帧具有独立生命周期。只有 Metadata 与全部 N 点都写完才调用 SDK 提交；不可复用仍由输出线程或 SDK 持有的存储。不得通过手动移动 SHM Ring 指针丢弃数据。
5. **硬件缺口单独处理**：若发生实际采集丢包、覆盖或一致性校验失败，当前部分块失效并丢弃；从下一可信采样组重新建立软件切分起点。这与下游背压造成的整 CPI 丢弃不同，单独计数，不补零、不把缺口两侧拼成一帧。

保证连续性依赖接收层能检测采集缺口及 DMA 覆盖。无法确认数据有效性时不得提交为正常 CPI，需报错或丢弃并重新建立可信起点；不能仅凭长度达到 N 就宣称完整。

输出序号出现间断是允许的。断链时 Sidecar 仍遵循其既有实时整帧丢弃语义，不提供历史帧重传；本方案保证交付帧完整，不保证每个采集帧必达。

## 下游接入

复用 [Sidecar](../../../infra/sidecar/README.md)：Source Upstream 为 `disabled`，Downstream 连接下游。Worker 与 Sidecar 共享输出 SHM，双方 IQ 契约版本及最大帧容量一致；单帧样本区为 `751206 × 4 = 3004824` 字节，加上 IQ v3 Metadata 的 `2136` 字节，SDK 载荷为 `3006960` 字节；Ring Slot 还需按现有 SDK/Sidecar 规则容纳帧开销。复用 `signalsource` 的输出配置并校验容量，不仅按样本区大小分配。
