# SignalSink 需求

**我的需求：**新增独立 SignalSink，作为基础设施中的数据接收与保存组件。只要上游满足框架裸帧协议及接入契约，无论是 IQ、脉压（PC）、RD 还是自定义数据，都能持续接收并流盘，完整保留帧边界、帧头、Metadata、Payload 和接收顺序，供后续离线分析及回放。单机与服务器部署使用同一组件，保存通过启动配置显式控制：默认关闭，单机录制时开启，uestcweb 部署时也可按需开启；关闭保存仍正常消费输入。录制数据持久保存，不静默覆盖已有文件；异常及丢帧必须明确报告。本需求不包含算法处理、MAT 转换或中间节点旁路录制。

**待确认项：**目标输入速率、录制时长和容量；是否按帧数或时长限制录制；文件滚动及容量用尽后的处理方式；磁盘跟不上输入时选择背压还是整帧丢弃；磁盘满或写入失败后停止还是继续消费；异常退出或断电允许损失的数据范围；是否需要同一录制会话混合不同类型或版本的帧。
